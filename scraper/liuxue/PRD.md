# 河狸陪留学三库产品需求文档

## 1. 结论

基于 Openision 已采集的公开数据，河狸陪可以建设三套相互关联的留学知识库：

- 专业库：以 `10,391` 条专业记录为主对象，服务选专业、查要求、看费用、看申请时间。
- 院校库：V1 先作为派生库，从专业库和案例库聚合生成院校画像，不假设已有完整独立院校详情 API。
- 案例库：以 `31,708` 条案例记录为证据层，服务相似案例参考、背景对比和选校依据说明。

产品表达必须使用“参考”“匹配”“相似案例”，不得包装成“录取概率”“保证录取”“官方录取线”。

## 2. 背景与数据事实

当前已完成 Openision 公共 API 分页抓取和数据校验：

- 专业记录总数：`10,391`
- 案例记录总数：`31,708`
- 筛选字典记录：`744`
- 专业 ID 唯一率：`100%`
- 案例 ID 唯一率：`100%`
- 案例 `major_id` 关联专业成功率：`100%`
- 案例 `target_school_id` 关联专业内院校成功率：`100%`

关键数据边界：

- 院校库在 V1 阶段是聚合库，不是独立抓取库。
- 专业国家应从 `major.school.country` 取值，不依赖顶层 `country`。
- 学费 `0` 表示未知或未披露，不表示免费。
- GPA 字段只能作为申请参考或案例背景，不得直接解释为录取线。
- 案例英语成绩覆盖不足，不能作为核心必填筛选。
- 来源链接、第三方图床、vendor URL 只作为内部溯源，不直接前台暴露。

## 3. 产品目标

### 3.1 用户目标

目标用户包括计划留学的学生、家长和顾问老师。用户需要快速回答：

- 我的背景适合申请哪些国家、院校和专业？
- 某个专业的申请要求、费用、学制和语言要求是什么？
- 和我背景相似的人申请到了哪些项目？
- 某所院校有哪些可申请专业，以及案例密度如何？
- 如何把候选专业、院校和案例整理成一份选校清单？

### 3.2 业务目标

- 将抓取数据从“原始资料”转化为河狸陪可使用的专业知识库。
- 让用户通过专业、院校、案例三种入口都能进入咨询转化路径。
- 为后续顾问工作台、内容 SEO、智能选校工具提供统一数据底座。

## 4. 非目标

V1 不做以下内容：

- 不承诺录取概率。
- 不输出“保录”“稳录”“冲刺成功率”等不可验证结论。
- 不建设登录态或私有数据抓取。
- 不直接展示第三方来源品牌链接、签名图片 URL 或敏感请求字段。
- 不做复杂机器学习模型，先使用可解释规则和统计聚合。
- 不把派生院校库描述为官方完整院校数据库。

## 5. 用户场景

### 5.1 学生按背景找相似案例

用户输入国家偏好、本科院校层级、GPA、专业方向和目标学位。系统返回背景接近的案例，并展示这些案例对应的目标院校、目标专业、录取年份和软背景摘要。

### 5.2 学生按专业查申请要求

用户搜索专业名称或方向，进入专业详情页。页面展示院校、国家、专业名称、学制、学费、语言要求、申请要求、申请时间和相关案例。

### 5.3 学生按院校看项目池

用户进入院校详情页。页面展示该院校覆盖的专业数量、案例数量、热门方向、可申请项目、案例 GPA 分布和推荐咨询入口。

### 5.4 顾问生成选校参考清单

顾问根据用户背景筛选案例，再从案例关联专业和院校，生成“冲刺、匹配、保守”三档候选清单。V1 中三档名称可以展示，但背后只能使用规则解释，不使用概率表达。

## 7. 核心流程

### 7.1 三库联动路径

1. 用户输入背景或选择筛选条件。
2. 系统先匹配相似案例。
3. 从相似案例关联到专业。
4. 从专业聚合到院校。
5. 用户将专业和院校加入选校清单。
6. 页面引导用户提交咨询表单。

### 7.2 专业详情路径

1. 用户搜索或筛选进入专业详情。
2. 查看申请要求、语言要求、学制、学费和申请时间。
3. 查看相关案例。
4. 加入选校清单或发起咨询。

### 7.3 院校详情路径

1. 用户进入院校详情。
2. 查看该校专业方向覆盖和案例数量。
3. 按方向筛选该校项目。
4. 查看案例分布和专业详情。

## 8. 推荐与匹配规则

V1 使用可解释规则：

- 国家匹配：用户偏好国家与专业国家一致优先。
- 方向匹配：用户目标方向与案例或专业方向一致优先。
- 背景匹配：本科院校标签一致或接近优先。
- GPA 接近：案例 GPA 与用户 GPA 差距越小越优先。
- 年份新鲜度：近三年案例优先。
- 数据密度：同专业或同院校案例数量多的项目优先。

展示文案规则：

- 可以说“与你背景更接近”。
- 可以说“近年有相似案例”。
- 可以说“申请要求需进一步确认”。
- 不可以说“录取概率为 X%”。
- 不可以说“达到该 GPA 即可录取”。

## 9. 数据质量规则

必须显式处理以下状态：

- `fee_known = false` 时展示“学费未披露或待确认”。
- `english_score_known = false` 时展示“语言成绩未披露”。
- `admission_year_valid = false` 时不进入年份筛选统计。
- `school_tag_normalized = unknown` 时展示“本科背景未披露”。
- 任何第三方来源 URL 只进入内部字段，不直接展示。

## 11. 验收标准

### 11.1 数据验收

完成标准：

- 可以从现有抓取数据生成 `program_library.jsonl`、`school_library.jsonl`、`admission_case_library.jsonl`。
- `program_library.jsonl` 记录数等于有效专业源记录数，预期为 `10,391`。
- `admission_case_library.jsonl` 记录数等于有效案例源记录数，预期为 `31,708`。
- 案例到专业的 join 成功率为 `100%`。
- 案例到目标院校的 join 成功率为 `100%`。
- 学费未知值不会被展示成免费。
- 无效年份不会进入年份筛选和年份统计。
- 前台输出数据不包含 token、cookie、签名参数、Authorization、FCAuthorization、OSSAccessKeyId、Signature、security-token。

### 11.2 功能验收

完成标准：

- 专业库支持搜索、筛选、详情查看和案例跳转。
- 院校库支持列表、详情、专业聚合和案例聚合。
- 案例库支持列表筛选、详情查看和专业跳转。
- 任一案例详情都可以跳转到关联专业。
- 任一专业详情都可以看到关联案例数量。
- 任一院校详情都可以看到专业数量和案例数量。
- 所有推荐说明都使用参考型表达，不出现录取保证或概率承诺。

### 11.3 质量验收

完成标准：

- 数据生成命令可以重复运行，输出记录顺序稳定。
- 运行单元测试通过。
- 运行数据质量报告，输出总数、缺失率、异常年份、未知学费、join 失败数。
- 报告中 `join_failed_cases` 必须为 `0`。
- 报告中敏感字段扫描结果必须为 `0`。

### 11.4 产品验收

完成标准：

- 用户可以在 3 次点击内从专业进入相关案例。
- 用户可以在 3 次点击内从院校进入专业列表。
- 用户可以在 3 次点击内从案例进入专业详情。
- 列表页空状态、未知字段、数据缺失都有明确展示。
- 页面文案不出现“保录”“保证”“成功率”“录取概率”等禁用表达。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 院校数据不是独立详情库 | 院校页信息不完整 | V1 明确标注为聚合数据，后续再补独立详情 API |
| GPA 被误读成录取线 | 用户误判申请难度 | 文案统一为申请参考和案例背景 |
| 学费 `0` 被误读 | 展示错误 | 增加 `fee_known` |
| 英语成绩缺失较多 | 筛选结果偏差 | 只作为高级筛选 |
| 来源链接合规风险 | 品牌和授权风险 | 前台隐藏第三方来源 URL |
| 数据来源偏 UK | 覆盖认知偏差 | 展示国家覆盖和数据说明 |

## 13. 里程碑

### M1：数据底座

- 生成三库 JSONL。
- 生成数据质量报告。
- 建立 join 和敏感字段测试。

### M2：查询能力

- 支持专业、院校、案例的基础查询。
- 支持核心筛选和排序。

### M3：页面原型

- 完成三库列表页和详情页。
- 完成三库互跳。

### M4：转化闭环

- 加入选校清单。
- 接入咨询表单。
- 记录用户选择路径。
