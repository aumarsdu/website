## 1. 目标、范围与授权

目标是建立可重放、可追溯、能可靠更新的五源内部资料库，支持项目筛选、比较和素材定位。首期保留供应商项目条目独立身份，不以相似题目自动合并供应商、期次、价格或权益。

本次授权只涵盖 Spec / Plan 文档。以下实现任务均未授权执行：代码修改、候选库构建、批量导入、切换、外部同步和发布须按各自阶段确认已有授权。计划不是授权回执。

首期包括 T01–T13；D01 是独立后续阶段，不阻塞内部资料库验收。不包括在线重新采集、自动下架、定时任务、客户数据、表单提交记录、CRM、订单、合同绩效系统、向量库、付费服务或对外发布。源文件、旧库和素材副本均不得因本计划被删除或覆盖。

技术候选：PostgreSQL 主库，JSONL 为批次交换，普通文件为素材载体。T01 锁定目标数据库主版本、运行环境和依赖版本；不能仅凭已有 44 张表判定复用成功。SQLite 可继续作为采集器导出，但不能替代目标数据库约束与事务测试。

## 3. 业务不变量与数据契约

### 3.1 实体及关系

下列是逻辑实体；物理表名和迁移映射由 T03 交付，优先复用可证明正确的现有表。

| 实体 | 必需语义 / 约束 |
| --- | --- |
| provider / source | 供应商与来源入口分开；集思未来海外/国内独立 namespace |
| batch / input_file | 批次描述不可变；文件相对路径、字节哈希、行数、范围、版本及完成状态可对账 |
| source_record | namespace + 经类型规则规范化的原生 ID 唯一；无可靠 ID 则登记候选身份 |
| content_payload | 脱敏后业务字段的确定性哈希；字段白名单和 hash_version 必须固定 |
| observation | 关联记录、内容、批次、证据定位及来源上下文；A→B→A 保留三次观察 |
| provider_project | 供应商项目条目；可关联多个 source_record；未确认跨供应商关系不自动融合 |
| offering | 属于供应商项目的期次；日期、周期、招生、币种及价格依据独立保存 |
| asset_blob / asset_location / asset_link | 字节去重、文件位置、业务引用分开；原图与处理图有派生关系 |
| extraction / field_evidence | 解析版本、证据位置、字段原值/规范值、置信度及复核结论 |
| manual_override / conflict | 人工修订绑定依据版本；新来源冲突可见；修改有审计、可撤销 |
| quality_issue / identity_link | 问题与身份合并/拆分决定可追溯；重新解析不能丢人工决定 |

“统一项目”首期等同规范化供应商条目。跨供应商研究主题仅是可选关联，不要求建设主题主表。导师采用来源身份；姓名和机构相同不足以自动合并人员。

### 3.2 批次 manifest

必需字段：`contract_version, batch_id, source_code, input_files[], scope, capture_mode, captured_at, observed_order, coverage, adapter_version, mapping_version, hash_version`。

- `input_files[]`：`relative_path, sha256, byte_size, row_count, format, role`；路径必须落在已批准根内，禁止路径穿越及越界 symlink。
- `scope`：入口、栏目/分类、数据粒度；`capture_mode` 为 full / incremental / archive / ocr。
- `coverage`：complete / partial / unknown，包含失败、截断、预期项和缺失项数量。增量 complete 只表示该增量范围完整。
- `observed_order`：来源可信版本或已核验快照顺序及其依据；缺失/不可比较时为 unknown。目录日期、文件 mtime、导入时间不得单独当作可信观察顺序。
- 批次 manifest 不含凭据、客户内容或绝对敏感路径。原始文件字节哈希与脱敏业务哈希分别命名，不能混用。
- 同 batch_id 不同 manifest_digest 必须拒绝；字节完全相同但新解析版本须新建 transformation_run，保留原观察，不伪造新的采集事件。
- 允许一个 batch 下多个上下文观察。幂等观察键由 batch + source_record + context_key + payload_hash 组成，不能只用 batch + record 丢弃多入口内容。

### 3.3 字段与更新规则

- 核心可搜索字段：供应商、来源身份、标题、分类、原始证据、最近观察、详情核验时间、质量状态。未得到标题但有稳定 ID 的记录保留为候选，不能伪造可展示标题。
- 可选字段：导师、机构、适合人群、先修要求、日期、周期、授课方式、招生状态、价格/币种、素材。可选不等于允许编造。
- 字段状态至少区分 value / explicitly_empty / not_provided / extraction_failed；金额用十进制定点数，0 不等于 unknown；日期保留原文、精度、时区或 unknown，不凭中文语境默认币种。
- 每个来源的 ID 类型规则显式配置；未经来源契约确认，不把 `001` 转成 `1`。元组用规范 JSON 等无歧义编码，禁止简单分隔符拼接。
- source 内容哈希排除采集时间、本地路径、随机值及处理日志；保留业务有意义的字段和关系。上下文 URL 与分类可单独保存，不能为消除伪版本而丢证据。
- 当前投影按可信观察顺序确定；旧批次晚到仅补历史。同序或不可比较的矛盾内容进入冲突，保留最后已验证投影或标为 unresolved，不能按输入行序选胜者。
- partial / unknown 批次不删除关系或推断下架；完整快照中的缺失只记录 not_seen。confirmed_unavailable 需要明确来源证据或有审计的人工决定。
- 人工覆盖层与来源层分开；覆盖包含理由、依据版本及作者标识。新内容与其冲突时显示冲突，不静默覆盖；移除覆盖后重新投影。
- 一个素材可关联多个项目；字节相同不意味着来源授权相同。下载、原始、处理、交付状态分别记录。
- 全量与增量只能根据已注册 manifest 组合，禁止默认 glob 所有日期目录、zip 和交付副本后相加。

### 3.4 结果与错误契约

所有命令支持只读 `--dry-run`、显式输入/输出根、边界限制。候选写入须目标检查；输出报告含 run_id、开始/结束、输入摘要、版本、分类计数、退出码与证据引用。

输入行必须互斥分类为 accepted / duplicate / quarantined / rejected；四者之和等于读取行数。expanded_observations、项目数、素材数另外计数，不与行数混算。一个输入文件解析失败时明确记录已读范围，不能报告全量完成。

数据库写入按实体另外报告 inserted / updated / unchanged / conflicted / failed 和实际提交回执；不能把尝试行数当 inserted。quarantined 不等于丢弃，也不等于可发布。

错误至少区分 contract_invalid、input_missing、input_changed、identity_conflict、ordering_unknown、schema_invalid、reference_missing、asset_unavailable、extraction_failed、transaction_failed、commit_unknown。报告只能保留安全字段和定位，不输出原始敏感值。

## 4. 通用 Definition of Done（所有任务强制继承）

- **功能 G-F**：满足该任务全部验收条件；每项条件对应测试/报告路径。缺证据即 NOT_DONE，不以“主要完成”放行依赖任务。
- **测试 G-T**：单元测试离线，使用合成或已授权脱敏 fixture；失败路径必须覆盖。涉及 SQL、迁移、事务的任务在 T01 锁定的真实 PostgreSQL 版本验证，禁止 SQLite 冒充。没有运行的检查标为 NOT_RUN。
- **质量 G-Q**：改动限定任务归属；复用项目锁文件和工具。新增 Python 公共接口有类型标注，获取、映射、验证、存储分离；不吞异常、不硬编码秘密、不增加无说明依赖。目标代码格式/lint/类型检查采用 T01 固定命令；存量失败在修改前登记，改动范围零新增违规，核心新模块必须全部通过。
- **交付 G-E**：附候选代码版本/文件哈希、输入 manifest_digest、数据库版本、命令与退出码、测试结果、未解决问题。回读 diff 与文档链接；没有未归属文件或不明副作用。
- **复核 G-R**：身份、映射、校验器、迁移及发布边界由未参与候选实现的审查者核对期望结果与反例。不得用候选自身输出生成唯一 golden；审查者可为 Owner 或获授权独立 AI，不假设另有员工。
- **状态 G-S**：任务仅为 NOT_STARTED / IN_PROGRESS / BLOCKED / DONE。BLOCKED 写明精确条件和缺失证据。文档完成不把任何实现任务标 DONE。

## 5. 任务规格

### T01 — 输入盘点、隔离与基线锁定

- **功能**：注册五家主事实源、归档/交付副本边界与已有实现；锁定候选数据库主版本、Python/依赖、质量命令、样本和环境。
- **输入**：五家指定目录、旧 DDL/工具、现有测试入口；不读取真实配置或凭据。
- **输出**：`baseline.json`、`source_registry.json`、`environment.json`、`quality_commands.md`、旧到新候选映射清单；试点样本 manifest。
- **边界**：不连接未知数据库、不启动旧集群、不扫描无关数据；无法确定主事实源的文件标为 excluded_pending_review。
- **功能验收**：五家均有入口/格式/范围/主键候选/采集时间依据；基线明确既有失败；候选库与源输出物理隔离并有目标身份校验；质量命令可执行且定义了检查范围。
- **测试**：路径穿越、越界 symlink、输入变更、空目录、交付副本误入各有拒绝 fixture；读取前后字节哈希变化检测有效。
- **质量 / DoD**：G-F 至 G-S；只读盘点不加载正文或大文件全量到 stdout。试点输入和工具版本可由另一人据报告定位和复现。

### T02 — 契约、身份与观察规则

- **功能**：实现第 3 节契约、ID 编码、哈希投影、字段状态及可信观察排序。
- **输入**：T01 来源注册与字段样本。
- **输出**：机器可校验 schema、每来源 mapping/ID/hash 配置、合成反例 fixtures、契约说明。
- **边界**：盐趣/引知无可靠 ID 时允许候选；不按标题或文件路径自动固化身份；禁止默认假定同供应商入口共用 ID 空间。
- **功能验收**：同内容同版本配置生成相同哈希；时间/路径变化不制造业务版本；有意义内容变化可检测；未知顺序与明确清空独立表达。
- **测试**：A→B→A、六种批次排列、同序冲突、ID 含分隔符、`0`/`001`、Unicode、空/缺失/失败、hash_version 升级均有显式预期。
- **质量 / DoD**：G-F 至 G-S；映射为可审查配置或纯函数，golden 在实现前冻结；规则变化必须有版本与兼容说明。

### T03 — 关系模型与可重放迁移

- **功能**：将第 3.1 节映射为 PostgreSQL 表、约束和版本化迁移；明确旧字段保留/转换/弃用。
- **输入**：T01 环境，T02 契约，旧 schema。
- **输出**：ER 图、数据字典、迁移序列、旧 ID 映射、schema_version、候选库初始化和恢复说明。
- **边界**：只在获授权隔离库执行；不原位替换旧库，不因首期缩减删除旧表；数据库缺扩展时显式失败。
- **功能验收**：来源键唯一且非空；观察只能指向同记录内容；当前指针不能跨记录；非法引用被拒绝；期次/供应商边界和字段状态可表达；迁移重跑不会重复或静默跳过不兼容变更。
- **测试**：空库建库、旧 schema 代表性副本升级、重复迁移、非法 FK/唯一键、错误当前指针、迁移中断与恢复；全部在目标 PostgreSQL 执行。
- **质量 / DoD**：G-F 至 G-S；DDL 与应用模型一致；不用全局 DO NOTHING 掩盖冲突；迁移评审通过并保留可恢复检查点。

### T04 — 三家结构化来源适配

- **功能**：接入集思未来海外/国内、中科、HIREP；把业务记录和多入口上下文映射到统一契约。
- **输入**：注册的 JSONL 及素材 manifest，T02 配置。
- **输出**：规范候选 JSONL、字段证据、上下文关系、适配报告。
- **边界**：不在线抓取；HIREP 同 business_id 多行必须保留不同 URL、分类和素材；旧 processed 与增量不得无条件相加。
- **功能验收**：四个来源入口均有适配结果；行数对账成立；同 ID 多入口只形成一个来源身份且所有合法关系可追溯；不可确定的导师/期次不自动合并。
- **测试**：每入口至少 10 个冻结代表样本，加同 ID 多入口、缺字段、新增/变更、乱序、截断 fixture；所有映射字段与人工期望逐项对比。
- **质量 / DoD**：G-F 至 G-S；适配器不直接写主库，公共逻辑与来源特例分开；公开接口有类型和错误类别。

### T05 — 素材注册、派生关系与文件定位

- **功能**：登记文件哈希、位置、来源引用及处理版本；原图、OCR 输入、处理图可追溯。
- **输入**：已授权素材清单、文件路径、项目候选关联。
- **输出**：blob/location/link/derivation 候选及完整性报告。
- **边界**：首次不搬移、不删除、不重新下载文件；同哈希的不同来源授权独立；压缩包默认不解压、不作为额外项目输入。
- **功能验收**：重命名不增加 blob；同文件多项目关联不丢；缺文件与未知位置分别可见；处理图能回到原图和处理版本；路径不能越界。
- **测试**：同内容多路径、改名、损坏、缺失、硬链接、越界 symlink、一图多项目、派生链环检测。
- **质量 / DoD**：G-F 至 G-S；哈希流式计算，输出只含必要元数据；计数分别报告文件位置数、唯一 blob 数及关联数。

### T06 — 盐趣 OCR 项目提取与复核

- **功能**：从既有 OCR CSV/文字位置中提取项目候选、日期/金额/导师等字段，绑定原图位置。
- **输入**：注册 OCR CSV、对应原图、引擎信息，T05 素材身份。
- **输出**：候选项目、extraction_run、字段证据/坐标、人工复核队列与覆盖报告。
- **边界**：不运行付费模型、不默认重做 OCR；处理成功不等于语义正确；缺原图或多项目边界不确定则隔离；标题改动不自动产生新项目。
- **功能验收**：每个输出字段可回到素材+文字块；低置信/冲突关键字段保持待复核；一图多项目和多图同项目可表达；复核后错误可追踪修正。
- **测试**：至少 20 张分层样本（不足则全量并声明），覆盖日期缺年、范围金额、币种缺失、导师同名、无标题及多项目；fixture 可合成补足边界，不充当真实准确率样本。
- **质量 / DoD**：G-F 至 G-S；golden 由非候选实现者核对原图；样本关键字段中“标为已复核”的值须 100% 正确、100% 有证据；可提取关键字段候选召回率至少 90%，未达标不得靠全部置空通过。比例报告列分子/分母和无法判断项，不外推为全量准确率。

### T07 — 引知公开归档项目切分

- **功能**：从已归档公开页面及素材关系切分项目条目，保留页面上下文与锚点。
- **输入**：注册公开 Markdown/JSON、页面快照及素材清单。
- **输出**：页面候选、项目段落、字段证据、素材关联、未归属内容报告。
- **边界**：不读取表单提交、客户/账号记录、会话或未授权 API 响应；导航、简介、公共页脚不能作为项目；缺稳定 ID 保持候选匹配。
- **功能验收**：每个项目回链到页面版本与段落；目录和详情重复可关联而不丢证据；未确认边界必须显式隔离。
- **测试**：至少 10 个真实代表段落（不足则全量），另加多项目、导航混入、同名、无标题、附件共享、页面更新 fixture；逐项比较切分边界与字段期望。
- **质量 / DoD**：G-F 至 G-S；已确认项目零导航误入、证据覆盖 100%；人工标注可识别项目召回率至少 90%，错误条目不得进入 confirmed；未知正文不得原样进入公开输出。

### T08 — 强校验与安全暂存

- **功能**：验证 manifest、文件/行数、schema、引用、身份和字段状态，输出可导入批次；采用临时目录完成后原子封存。
- **输入**：T02 契约、T03 约束描述、任一适配器候选。
- **输出**：不可变 validated manifest、拒绝/隔离清单、完整对账；validation_version 和输入 digest。
- **边界**：空输入默认失败；合法零结果必须 manifest 明示并有完整性证据；缺父表不能跳过；必需核心实体失败则整个批次不可导入。可选字段隔离按契约处理。
- **功能验收**：同输入可复现相同判定；输出无未声明旧文件；任何验证后输入变更使资格失效；敏感键、URL 参数及自由文本只输出已批准字段。
- **测试**：空目录、缺表、坏 JSON、中途截断、计数不符、外键缺失、跨记录指针、敏感合成字符串、遗留文件、运行中断均被正确拒绝/隔离。
- **质量 / DoD**：G-F 至 G-S；独立反例验证，不以自身 schema 生成的正常样本作为唯一证据；禁止打印原始行和大 SQL。

### T09 — 幂等导入与提交回执

- **功能**：只接受 T08 封存输入，原子提交一个有大小上限的批次；更新身份观察和内容关联，生成实际回执。
- **输入**：validated manifest、目标候选库身份、T03 schema_version。
- **输出**：批次账本、实体写入统计、commit receipt、可重查状态。
- **边界**：单一受控 Writer；并发第二写入拒绝或等待到明确超时。超限批次先按契约拆成有父 manifest 的独立批次，不静默改为部分提交。提交超时为 unknown，先查回执；无回执且确认事务终止后才按幂等键重试。
- **功能验收**：同输入重放零额外实体/观察；批次标识重用但输入不同必拒绝；旧批次不倒退当前状态；多上下文同批次不丢；人工数据不覆盖；失败原子回滚。
- **测试**：真实 PostgreSQL 上验证 A→B→A、六种排列、同序冲突、并发写入、写到一半断连接、提交前后断连接、违反 FK、回执重查与有限事务重试。
- **质量 / DoD**：G-F 至 G-S；SQL 参数化或受控 COPY；状态计数来自已提交结果；锁/连接释放可验证；没有需要“重跑看看”的未知提交遗留。

### T10 — 当前投影、人工修订与质量状态

- **功能**：生成当前供应商项目和期次投影，管理字段覆盖、冲突、not_seen 与质量队列。
- **输入**：T09 历史观察及证据、显式人工修订请求。
- **输出**：内部 current projection、字段来源、审计记录、可撤销修订、状态变更报告。
- **边界**：不自动发布/下架；不按同名自动合并导师；complete 增量不能删除全量关系；多期次独立，不统一 default 期次吞并。
- **功能验收**：来源更新与人工值并列可查；删除覆盖恢复正确来源值；同序冲突和未知日期不假装确定；同供应商不同期次及不同供应商同题目保持可区分。
- **测试**：覆盖后更新、撤销、明确清空/未提供/失败、旧快照晚到、关系撤回范围、ID 复用、合并后拆分恢复证据、两期次价格日期不串。
- **质量 / DoD**：G-F 至 G-S；投影可由历史+人工账本重建，重建结果与在线结果一致；人工修订接口本地认证并审计。

### T11 — 内部检索与结果边界

- **功能**：提供内部项目搜索、来源/供应商/分类筛选、期次筛选、详情与素材定位；每项目一张列表卡，期次以数组展示。
- **输入**：T10 当前投影、安全查询参数、T01 冻结查询集。
- **输出**：分页结果、独立准确 total、字段证据链接、未知/过期/冲突提示。
- **边界**：只启用明确内部接口并默认 loopback；本地写接口验证认证和请求来源。不得挂载旧 visibility/public 路由，不自动导出公开文件；分页稳定排序含唯一 ID。
- **功能验收**：同项目多期次不重复卡片；空页仍返回准确 total；组合筛选、中文短词、别名与未知值语义有定义；无导师项目仍能显示分类。日期/价格筛选默认排除未知，可显式包含未知但不得表示匹配。
- **测试**：固定至少 20 条有人工相关性标注的查询；golden 筛选结果精确相等、分页无重复遗漏；Top-10 召回率至少 90%（按每查询 min(10,相关项数) 为分母）；权限、路径穿越、通配符、恶意排序、公开路由拒绝有测试。
- **质量 / DoD**：G-F 至 G-S；记录候选数据量、硬件和数据库版本；20 查询每条预热 1 次再测 5 次，共 100 次串行测量 p95 ≤ 1 秒；不得通过删记录/降低正确性达标。目标失败先调查询/索引，不自动引入新搜索服务。

### T12 — 备份恢复与候选切换演练

- **功能**：制作并恢复数据库、人工账本、版本配置和素材清单对应的一致备份，演练显式切换/回退。
- **输入**：候选库、不可变素材、T09 回执、T10 修订账本。
- **输出**：backup manifest、恢复日志、计数/哈希核对、切换与回退 runbook。
- **边界**：恢复到新目标；演练不触碰旧库/源文件；没有授权不实际切换。备份必须覆盖素材内容或可验证独立备份位置，只有路径清单不算备份。
- **功能验收**：恢复后项目/观察/人工修订/关联计数与快照一致，已登记素材哈希全部一致；未知/缺失素材与备份前问题清单一致，无新增遗漏；切换失败能回原只读目标。单写入阶段冻结写入后切换，避免回退丢新修订。
- **测试**：有效恢复、缺素材、损坏 dump、schema 不匹配、切换失败、恢复时断开、备份后新增记录不被误计为快照丢失。
- **质量 / DoD**：G-F 至 G-S；试点目标 RPO 为最近已封存批次及已确认人工修订零丢失（确认前需持久化独立恢复证据），RTO ≤ 60 分钟；计时从恢复命令到查询和完整性通过。未满足不能放行 T13。

### T13 — 五源端到端验收与迁移决策

- **功能**：在候选环境走完五源输入→适配→校验→导入→投影→搜索→恢复，形成 go/no-go 结论。
- **输入**：T01 冻结试点，T04/T06/T07 数据，T08–T12 证据。
- **输出**：acceptance_matrix、逐来源质量/覆盖报告、问题登记、容量测量、迁移决策记录。
- **边界**：试点每来源最多 50 个候选记录（集思未来两入口各最多 25），素材最多 300 个、总大小最多 2 GiB；任何超限先报告并停止扩展。真实数据无素材样本不靠合成样本替代准确率验收。全量候选导入和实际切换另行授权。
- **功能验收**：五家均完成各自验收；所有强制测试和对账通过；关键字段证据覆盖 100%；公开路径关闭；不存在 P0/P1 未解决问题；P2 必须有影响说明和 Owner 明确接受后方可 go。
- **测试**：从空候选库完整重放两次，比较规范数据摘要；随后跑异常/恢复用例；验证测试报告与实际版本一致，不能复用修改前证据。
- **质量 / DoD**：G-F 至 G-S；独立审查者复核输入预期与实际查询，逐项签署 PASS/FAIL/NOT_RUN。go 仅指允许提出全量候选迁移申请，不等于已授权、已切换或业务效果已验证。

### D01 — 后续公开发布边界（首期排除）

- **功能**：经单独授权后提供独立公开投影、版本发布/撤回、素材权限与价格策略检查。
- **输入**：T13 已验收基础、具体发布版本、明确授权范围/期限、审核证据。
- **输出**：只含白名单字段的公开快照/API、发布回执、撤回和缓存失效记录。
- **边界**：默认拒绝；未知/过期/撤销授权不能发布；禁止内部简介或内部价格回退；新来源版本不会自动继承旧版本审批。禁止沿用旧 visibility 直接发布。
- **功能验收**：发布前核验具体内容版本、主体/素材范围和期限；所有公开查询只读当前发布版本；撤回后 API、静态导出、应用缓存均不可返回撤回数据。
- **测试**：无权/过期/撤销、并发审批与发布、来源更新、价格隐藏/区间、旧缓存、静态导出、未认证写入、恶意请求和字段泄露反例；验收前固定撤回生效 SLO，必须实测达标。
- **质量 / DoD**：G-F 至 G-S；专门安全与授权审查通过；公网运行环境和身份方案须另定规格，不以本地 loopback 当公网鉴权。外部发布仍需对象与动作授权。

## 6. 严重度、放行与未验证项

- P0：泄露/越权、不可恢复的数据损坏；立即停止受影响动作。
- P1：身份误合并、静默丢失、错误当前投影、无证据关键字段被标已确认、核心测试无法复现；阻塞依赖与放行。
- P2：不影响真实性和边界的可见性/性能/非核心体验问题；不得私自降低验收阈值。
- 优先级 P0/P1/P2 的排程含义见 Plan；问题严重度与任务优先级不得混用。

仍未验证：实际 PostgreSQL 状态/版本、五源真实字段抽取准确率、查询性能、全量容量、备份恢复时长、来源时效及外部授权。T01–T13 将逐项获取证据；不存在“100% 无未知风险”的完成定义。
