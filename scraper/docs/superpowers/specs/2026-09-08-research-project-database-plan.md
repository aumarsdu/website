## 1. 排程规则

任务优先级：P0 = 先解决的数据契约/正确性门禁；P1 = 首期必须交付能力；P2 = 独立后续阶段。这里是排程优先级，不是缺陷严重度。

只有依赖任务 DONE 且证据版本匹配才可开始依赖写入；只读分析可以提前。独立审查未完成的规则/迁移/校验器任务保持 IN_PROGRESS。表中顺序为默认串行顺序，不承诺未经基线测量的工期。

## 3. 里程碑与停止门禁

### M0 — 进入隔离实施前

- 检查当前对话是否已有必要本地实现与候选环境授权。
- 复用任务隔离环境；这里是 local-only archive，不执行 Git 同步。对非 Git 跟踪部分采用独立代码目录和候选数据根，记录源文件哈希；不直接修改其他任务脏文件。
- 先读适用目录规则、核对目标 diff，再执行 T01。
- 若没有实施授权，交付本 Spec/Plan 即停止，不将计划当执行批准。

### M1 — 输入与数据库契约可验证

- 包含 T01、T02、T03、T08。
- 交付：输入注册、环境、冻结 fixture、DDL/迁移、强校验。
- 放行条件：真实数据库约束与反例测试通过；没有开放的身份/观察顺序 P1 设计问题。
- 失败处理：保留候选环境与证据；不升级旧库；缺来源规则只阻塞受影响适配器。

### M2 — 五源样本都可表达

- 包含 T04、T05、T06、T07。
- 试点上限：每来源最多 50 个候选（集思未来两入口各最多 25）；300 个素材，2 GiB；不得为达到阈值静默删除困难样本。
- 交付：五源适配输出、字段/素材证据与独立标注比较报告。
- 放行条件：五家各自 Spec 测试通过，三家结构化成功不能替代另外两家。
- 失败处理：如果 OCR/页面无法可靠提取，保持候选和人工复核，不降级为自动确认；阈值变更需明确业务决策及规格修订。

### M3 — 内部候选库可靠可查

- 包含 T09、T10、T11。
- 交付：真实提交回执、历史/投影、人工修订、内部查询和性能证据。
- 放行条件：批次重放、乱序、冲突、事务故障、分页和本地访问边界全部通过。
- 失败处理：提交结果未知时先查回执；不在旧库“再试一次”；不启用旧公开路由作为替代界面。

### M4 — 可恢复且允许提出全量迁移

- 包含 T12、T13。
- 交付：恢复演练、端到端验收矩阵、问题登记和 go/no-go。
- 放行条件：无 P0/P1，P2 由 Owner 显式接受，所有证据对应当前候选版本。
- go 的含义：可提交具体全量候选导入方案，列确切输入、目标、数量/字节上限和回退点，请求该阶段授权。
- 全量候选导入后须复跑计数/完整性/查询容量与恢复检查，试点通过不自动证明全量通过。实际使用目标切换是再下一阶段，需独立授权与冻结写入窗口。

### M5 — 可选对外发布

- D01 不计入首期完成率，不因为内部验收通过而自动启动。
- 实施前补齐具体发布渠道、运行环境、身份策略、授权证据和撤回生效 SLO。未有这些输入时状态为 BLOCKED，而不是降低门槛。

## 5. 测试执行与证据协议

T01 将下列检查名称映射为真实可运行命令，并记录工具版本。此处不编造尚不存在的 CLI 或 pytest 路径。

| 检查 | 覆盖 | 运行时点 |
| --- | --- | --- |
| contract-unit | 身份、哈希、字段状态、观察序、manifest | T02 后及规则变化后 |
| adapter-fixture | 四结构化入口、OCR、页面、素材 | 各适配器完成及映射变化后 |
| validator-negative | 空/缺/坏/越界/敏感合成输入 | T08 后及契约/校验变化后 |
| postgres-integration | 迁移、约束、导入、并发、提交未知 | T03/T09 后及 SQL 变化后 |
| projection-query | 人工覆盖、关系、期次、分页、筛选 | T10/T11 后及投影变化后 |
| recovery-e2e | 备份、恢复、两次重放、切换失败 | T12/T13；全量候选规模再次验证 |
| quality | 目标格式、lint、类型检查及 diff 审查 | 每任务完成前；记录存量失败 |

每份验收记录至少包含：task_id、Spec 版本/哈希、候选版本、输入 digest、环境、命令、退出码、测试数量与失败列表、安全日志路径、验收项→证据映射、审查者、时间、剩余问题和状态。

测试真值不能全部从候选实现产生。真实语义样本人工标注与合成边界测试分开计数；模型测试、集成测试、业务验收分开报告。

一项检查失败则该条件 FAIL；缺环境/未执行为 NOT_RUN；均不得记 PASS。已知基线失败不自动阻塞无关任务，但必须证明没有影响本任务验收，核心新模块不能借存量失败豁免。

## 6. 风险响应、资源限制与阶段完成判定

- 每任务先运行最窄测试；通过后仅扩展受影响检查，不无限重复已有证据。
- 同一失败先收集新证据；两次无新增信息的修复尝试后停止该分支，记录精确阻塞。不能为了“100% 信心”无限循环。
- 默认 1 Writer；独立复核不转移实现归属。没有可用独立复核者时，受影响门禁保持未完成。
- 不新增周期任务、付费调用或线上采集。日志超过数百行/100 KB 先落盘再读摘要。
- 发现敏感内容只记录位置/类型，不展示值；未知原始字段进入隔离，禁止复制到公开输出。
- 工具/数据库版本、源文件或规则变化使证据失效时，重跑受影响任务；不把旧报告当新版本通过。
- 首期 DONE = T01–T13 全部 DONE，强制证据齐全，M4 独立审查通过。此状态仍不是已全量迁移、已切换、已部署或线上业务效果已验证。
